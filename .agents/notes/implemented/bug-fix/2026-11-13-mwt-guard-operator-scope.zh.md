# Agent Note: The MWT.ONE operator guard belongs to declared operators

Status: implemented

[English](2026-11-13-mwt-guard-operator-scope.md) | 中文

## 问题

一个 Marluvas 邮箱——在自身公司内控制台角色为 Admin/CEO 的外部租户——打开它的 Mesa de trabajo，看到 176 项。没有一项属于它自己：队列里是 Muito Work Limitada 和其他客户的 expediente 任务，还有一长列完全相同的 `Dead letter: mwt-revisar`。该所有者从未连接过邮箱，所以这件事与邮件无关。

代码里有两个事实产生了那个看板。`ensureBuiltinRoutines` 为每一个部署挂载了 `mwt` MCP 工具的所有者预置 MWT.ONE 守卫例程（`Vigía MWT.ONE`，步骤 `mwt-revisar`，每 6 小时循环一次）。工具挂载是部署级的，因此每个登录身份都得到了一个会审阅整个账本的例程，并会就任何客户创建 expediente 任务。其次，在 `failurePolicy: 'review'` 下失败的步骤，会为每一次失败的执行登记一条 `Dead letter:` 项，既没有键也没有去重，所以一个每次触发都失败的例程会自己把队列撑大——按该频率每天四条。

守卫自己的提示词让特权外部者的问题更糟：它只在 Admin/CEO 的情况下要求检查 SAP，所以外部 Admin/CEO 会找到更多本公司的待办，而不是更少。

## 决定

**只有当部署声明某身份为操作者时，该身份才运行守卫。** 两个经过校验的 `Config` 字段指定这个集合：`mwtOperatorEmails`（精确邮箱，默认为空）和 `mwtOperatorDomains`（默认 `['muitowork.com']`，即本公司的员工）。`isMwtOperator` 以不区分大小写的方式，把当前身份的邮箱——网关以 `ownerId` 注入——与两份列表比较。角色从不参与决定：Admin/CEO 描述的是该身份管理的租户，而不是守卫所读的账本。

**预置与撤销是同一次收敛步骤。** 当 `hasMwtTools() && isMwtOperator()` 成立时，`ensureBuiltinRoutines` 预置守卫；否则它撤销可能已存在的内容：例程处于活动状态时暂停它，然后以闭集原因 `ERROR_ORIGEN` 关闭该例程登记过的每一条非终态项。严重级别仍为空的项会先被定为 `LOW`/`RULE`，因为看板只关闭严重级别已确定的项。无论 MWT 工具是否挂载，撤销都会执行，因此移除工具的部署仍会清理守卫留下的内容。

**关闭，而不是删除。** 丢弃会保留每一行及其原因，所以看板留下了部署级例程在错误 Mesa 上登记过什么的审计痕迹。任何人已批准、委派或关闭的内容都不会被触碰：该过程跳过终态行，以及记在其他例程名下的每一项。

## 考虑过的替代方案

**以控制台角色作为门禁。** 否决：它看起来是显而易见的信号，却给出完全错误的答案。报告中的所有者*正是* Admin/CEO；缺失的事实是那个角色管的是哪个账本。

**在 Mesa 中对操作者域之外的读者隐藏这些项。** 否决：看板没有按读者粒度的可见性——一项属于它的所有者和公司——而且隐藏会让例程继续运行，继续读取整个账本并继续消耗模型调用。

**对非操作者停止挂载 `mwt` MCP 客户端。** 否决：`client_b2b` 用户合法地查询自己的 expediente，MCP 已按转发身份限定范围。为修复一个预置错误而移除工具会破坏客户端产品。

**删除已登记的项。** 否决：关闭会保留例程曾声称什么、以及为何被撤回，这正是日后告诉读者该队列曾经出错的信息。

## 后果

操作者无需配置即可保留守卫，因为 `muitowork.com` 是 schema 默认值；操作者集合不同的部署显式声明它。外部租户失去该例程及其登记的工作，并保留自己的邮件、工作流和手工项。撤销是读路径上的一次写入，每进程一次，与那里已有的、会重写部署级例程定义的收敛一致；看板拒绝关闭的项会留在原处，调用方记录这次失败而不是静默丢弃。

有一个缺口按设计保留：该身份门禁决定谁获得守卫，而不是 MWT.ONE MCP 回答什么。直接调用 `mcp__mwt__*` 的租户仍会看到控制台授予其邮箱的内容，所以想让某租户看不到 MWT.ONE 的部署必须在 MCP 中实现，而不是在这里。

## 测试

`packages/faberloom/view/tests/mwt-guard-scope.spec.ts` 固定了这条边界：由邮箱声明的操作者会预置并激活守卫；外部租户会暂停它，并且只关闭守卫登记的行，跳过已关闭的行和另一例程的行，并在丢弃前先确定为空的严重级别；已暂停的守卫保持不动；从未持有守卫的所有者不会引起看板读取；在没有 MWT 工具时撤销仍会执行，在部署未挂载看板时会暂停例程。`packages/faberloom/view/tests/email-actions.spec.ts` 保持域默认值预置的用例为绿，因此操作者路径未变。
