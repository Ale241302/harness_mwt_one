# Agent Note: 邮件创建空间的动作会复用空间并打开其会话

Status: implemented

[English](2026-09-24-faberloom-space-from-email-reuse.md) | 中文

## Problem

邮件阅读弹窗里的 Space 动作会创建空间，但浏览器没有进入它：界面仍停在原本已激活的会话（一个无关的工作区），于是新建的空间看起来建好了却用不了。再次用同一主题点击 Space，会再建一个同名空间，而不是把这封新邮件追加到已有记录。

## Decision

`spaceFromEmail` 按标题匹配已有空间，并在最终得到的空间里打开一个会话。

- **按标题复用。** 该远程方法列出所有者的空间，取出第一个标题（去空白并转小写后）与请求名称相等的空间；存在则复用，否则用选定 agent 新建。复用不会覆盖已有的 agent；邮件正文被记忆、附件被挂到匹配到的空间，因此同一主题的后续邮件会归入同一空间。
- **返回刚注册的工作区。** 该远程方法返回 `ensureSpaceWorkspace` 已解析出的 `Workspace` 对象，而不是重新解析空间工作目录、再按路径到注册表里查找。那次查找与注册存在竞态：`registry.list()` 尚未包含 `registry.create()` 刚返回的行，导致 `workspaceId` 为 `null`，面板据此认为“无可打开对象”而保持当前会话不变。

## Alternatives considered

**用消息 id 或时间戳命名空间。** 这样永不冲突，但同一客户线索会散落在多个空间，无法累积成一条记录，而这正是该工作流的意义。

**严格按标题精确比较。** 后续邮件很少逐字节复现主题的空格与大小写，精确比较仍会重复；去空白并折叠大小写是能匹配用户心中“同一个空间”的最小规则。

**保留注册表查找并加一层搜索兜底。** 一次操作里两次读同一注册表，再用兜底掩盖延迟，代码更多；直接返回 `ensureSpaceWorkspace` 的结果才是正解。

## Consequences

- 空间现在是主题的稳定键：反复点击 Space 会累积记忆与文件而非制造重复；这也意味着两封主题相同但内容不同的邮件会落进同一个空间（对该工作流而言是有意为之）。
- 当挂载了工作区注册表时，面板总能拿到可用的 `workspaceId`，Space 动作因此能进入新会话；未挂载注册表的部署仍会保存邮件并返回 `workspaceId: null`。

## Testing

`packages/faberloom/view/tests/space-from-email.spec.ts` 覆盖：新建空间返回其新工作区 id、同标题再次点击复用空间（不调用 `create`，记忆与附件写入已有 id）、以及注册表缺失时返回 `null` 但仍创建空间。
