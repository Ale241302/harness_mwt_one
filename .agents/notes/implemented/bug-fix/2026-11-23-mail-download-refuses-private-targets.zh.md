# Agent Note：邮件下载拒绝私有目标并限制正文大小

Status: implemented

[English](2026-11-23-mail-download-refuses-private-targets.md) | 中文

## 问题

`faberloom_mail_download` 把发件人控制的链接直接交给 `fetch`，后者会自行跟随重定向并把整个响应读入内存。一封邮件可以把 agent 指向 `127.0.0.1`、部署的私有网络、元数据端点，或一个永不结束的服务器。该工具还会按发件人选定的名字写入会话目录。

## 决定

### 由这里解析并检查主机

`download.ts` 只解析一次主机名，只要任一答案属于 loopback、私有、链路本地、运营商级 NAT、组播、保留或未指定范围就拒绝请求。字面地址无需解析即可检查，IPv4 映射的 IPv6 字面量采用其内嵌 IPv4 地址的结论。检查每个答案而非只看第一个，避免混合 DNS 答案藏起私有条目。

### 套接字固定到已检查的地址

请求使用固定的 `lookup` 打开，返回已经检查过的地址，同时 `Host` 头与 TLS 服务器名保持原主机名。因此检查之后的第二个 DNS 答案无法改变连接目标，这正是仅做预检查会留下的 DNS 重绑定缺口。

### 每次重定向都重复整套检查

最多跟随五次重定向。每一跳都重新按绝对 `http` 或 `https` URL 解析、重新解析主机、重新检查后才建立连接；指向 `file:`、私有地址或缺少目标的跳转都会终止链条。

### 正文在流式读取时受限

上限为 20 MB。声明超过上限的 `content-length` 在读取前即被拒绝，流在第一个越界的块处被切断，因此缺失或作假的长度头都无法耗尽进程。整个操作有 30 秒上限。

### 下载绝不替换已有条目

名称被缩减为 basename，非法字符变为 `_`，`.` 或 `..` 回退为 `descarga`。文件以 `wx` 标志写在第一个空闲名称下（`oc (2).pdf`），因此预先放在目录里的符号链接既不会被跟随也不会被覆盖。目录必须是真实目录，用 `lstat` 检查。

## 备选方案

**下载主机允许清单。** 否决：邮件链接指向任意客户与承运商域名，清单会很快失效。

**单独的下载代理。** 本切片否决：它新增一个带认证与配额的公共 HTTP 面，而该工具已在 owner 的会话内运行。

**信任 `content-length`。** 否决：它由发件人控制，而且经常缺失。

## 后果

私有或超限的链接会以模型可处理的消息失败。一个同时发布私有答案的合法主机也会被拒绝，这是保守的方向。每次下载都是新文件；工具绝不覆盖 owner 已放在 `correo-adjuntos` 里的内容。

## 测试

`corepack pnpm run typecheck` 通过；`vitest run packages/faberloom/tool-faberloom/tests` 通过 179 项测试。新增覆盖：两个地址族与映射字面量的阻断表；loopback 字面量在未解析时即被拒绝；含一个私有答案的名称被拒绝；公共名称返回已检查地址；跳转到私有地址在请求一次后被拒绝；跳转到公共地址会再次解析并跟随；声明与流式两种超限正文都被拒绝；恰好等于上限被接受；第六次跳转被拒绝；穿越名称回退；已有名称变为 `(2)`；符号链接不被跟随。
