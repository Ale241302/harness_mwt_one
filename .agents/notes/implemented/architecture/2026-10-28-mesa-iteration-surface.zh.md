# Agent Note：Mesa 迭代界面读取、续期并记录

Status: implemented

[English](2026-10-28-mesa-iteration-surface.md) | 中文

## 问题

迭代机器随板服务一起交付时已能开启、应用与释放一次尝试，Mesa 也已经显示尝试的阶段、草稿与出口。有三处缺口让这块界面无法独立成立。

第一，没有任何东西为尝试续期。D-09 签署的是每 30 秒活动续期、15 分钟过期，而没有任何客户端续期：真实工作在一刻钟内就丢掉了锁，唯一的回途是等尝试结束后重新打开条目。

第二，面板分不清自己的尝试与另一个标签页的尝试。§9.7.1 让尝试而不是用户成为锁的主体，并要求第二个标签页以阅读模式显示条目与该尝试的状态；视图返回的投影只带到期时刻，不带持有它的会话，于是第二个标签页渲染出一个并不属于它的尝试的出口。

第三，W-34 只做了一半。`applyIteration` 把所选范围记在审计事件上，却没有任何东西抵达纠正登记表，于是行内编辑与已应用的迭代都没有留下纠正，学习包的 `onCorrection` 也没有任何调用者。

## 决定

**视图以十一个 Remote 拥有迭代界面。** `boardIteration` 读取尝试，`boardIterationContext` 读取钉住的对话上下文，`boardIterationStart` 开启一次尝试，`boardIterationSaveDraft` 保存它的工作，`boardIterationApply` 以一个新区本关闭它，`boardIterationPause` 覆盖各个出口，`boardIterationCancel` 丢弃工作，`boardIterationResume` 重开保留的草稿，`boardIterationRecover` 把被转移的草稿变为该尝试的草稿，`boardIterationDraft` 读取该草稿及其差异，`boardIterationRenew` 延长锁。它们没有一个向客户端询问调用者是谁或可以做什么：身份、所有者、公司与只读都作为部署配置到达，板在每次读写之前执行自己的授权。写操作唯一指名的是标签页会话，因为 §9.7.1 让尝试而不是用户成为锁的主体：每个受锁约束的写入——保存、续期、暂停、取消、应用——以及重开与恢复都携带 `actorSession`，视图原样转发。面板依据尝试的阶段与持有它的会话来决定提供什么；板决定什么被允许。

**对话上下文是钉住、最小化并按数据分级设限的。** `boardIterationContext` 返回条目 id、标题、账户、空间 id 与可读的空间标题、版本、摘要、工作草稿的摘要与轮数。板按所有者与公司过滤条目，空间服务过滤标题，不携带账户历史、空间记忆或其他条目（§8.5）。只有当条目的数据分级不高于部署为该会话所用提供者声明的上限时，摘要与工作草稿才会随行（W-48）。上限是经过校验的 `Config` 字段 `providerDataClassCeilings`，加上会话未指名提供者时使用的 `defaultProvider`；两者都是部署配置而非产品规则，因为逐级细节由 POL_DATA_CLASSIFICATION 拥有。回退是拒绝：映射未指名的提供者、未指名提供者且未声明默认值、以及分级仍为暂定的条目（D-05、W-99）都只收到元数据，工作草稿甚至不会被读取。面板把该值交给任务对话作为起始提示词（W-32），被扣留的摘要以明确的缺失出现在提示词中，而不是一行空白。

**冲突转移的工作出现在仍然有效的条目上，并且可以恢复。** `assignWorkspace` 回答保持有效的那个条目，因此视图读取该条目的详情，而不是面板原来持有的 id：关闭了读者所开条目的冲突会落到保持有效的对端。`boardDetail` 投影 `transferredDrafts`——板从被关闭条目移走的迭代草稿与编辑草稿，各自带有键、基础版本与来源——面板以“较早版本”的措辞把它们渲染为一条提示，提供比较与恢复（§2.3、W-98）。`boardIterationRecover` 转发草稿键与标签页会话：板拒绝未转移到本条目或超出保留期的键，在草稿基础版本仍是当前版本时在其上开启尝试，否则把草稿标记为已过期并返回差异而不写入条目（W-68）。恢复后的草稿成为该尝试的草稿，因此工作由常规的带范围“应用”写入，而不是由恢复本身写入。比较会读取已存储的草稿及其差异字段。该提示遵守单提示规则：与其他提示并存时，它会像其余提示一样折叠在计数器之后（E4）；进行中的尝试只保留比较，因为条目已经拥有一份草稿。

**界面提供三个出口与一次应用。** 进行中尝试的操作栏带有带范围选择器的“应用”、“丢弃我的更改”、“保存并退出”与“带到 SpaceLoom”；“未解决返回”位于应用对话框内。每一个都会释放锁、让尝试 id 失效、保留工作草稿，并把人带回同一个条目与它现在的版本（W-33、W-67、W-97）。待处理候选会阻塞应用，直到人选择 adopt 或 keep。

**本标签页只为自己持有的尝试续期。** `boardIteration` 投影 `lockBy`；当尝试进行中、锁指向本标签页的会话（或不指向任何会话）、且文档可见时，面板按投影的 `renewalSeconds` 启动一个计时器。尝试结束与面板卸载时它被清除。被 `LOCK_LOST`、`ITERATION_STALE` 或 `LOCK_HELD` 拒绝的续期意味着尝试已不属于本标签页：在丢弃本地镜像之前，面板为该已死尝试的 id、代次与会话再加当前文本再发一次 `saveIterationDraft`，于是板把该文本归档为该尝试的草稿，保留的草稿仍会提供它（W-43、W-57）。若板连这一次写入也拒绝——被他人持有的锁总是如此——文本留在面板中，单行消息说明此事，而不是无声丢弃。`LOCK_HELD` 同时把尝试读作另一个标签页的：条目变为只读，另一个标签页的提示取代出口，而续期从不写入工件。

**另一个标签页的尝试只读且不提供任何出口。** 当锁指向另一个会话时，条目以只读渲染：草稿区与严重度、空间控件保持禁用，一条提示说明另一个标签页正在迭代该条目，出口既不渲染也不由键盘打开，因此本标签页无法覆盖另一个标签页的工作。没有跨面板跳转；提示就是全部的可供性。板仍然执行状态、id、代次、会话与基础版本，因此该规则是拒绝之上的礼貌，而不是它的替代。

**视图尽力而为地桥接两种纠正。** 应用成功后，它以来源 `iterate` 调用一次 `onCorrection`，携带所选范围、尝试存储的摘要作为指令、应用版本与面板读到的条目之间不同的字段作为差异、轮数，以及条目的血统、数据分级与所用字段。`boardSaveEdits` 成功后，它以来源 `edit`、范围 `puntual` 为每个变更字段调用一次 `onCorrection`，携带该字段的前值与后值以及条目的分级。两者都在板的提交之后运行，因此都是尽力而为：失败会返回一条消息交给面板单行写入反馈，绝不使命令失败或回退，这意味纠正可能缺失而条目已经提交。视图不创建候选；学习包依据范围决定那件事，而暂定数据分级会记录纠正但不喂给任何派生结果（D-10）。

## 考虑过的替代方案

**由宿主按计划续期。** 服务端清扫者为每个进行中的尝试延长锁，可以扛住标签页关闭，也不需要客户端计时器。它落选是因为 D-09 签署的是按活动续期：没有读者却延长的锁会让被放弃的尝试在进程存活期间一直活着，而面板本来就知道文档何时可见、尝试何时属于自己。

**让面板推导谁能迭代。** 在每个 Remote 上传递调用者或权限标记，可以让界面按角色隐藏控件。它落选是因为身份规则是网关注入所有者、客户端从不指名它，也因为客户端权限检查只是建议，板仍然必须重复执行。

**在板命令之前发送纠正。** 先写纠正会让失败的提交留下一条关于从未发生的更改的纠正。它落选是因为工件才是事实：提交在先，无法跟随的纠正被上报而不是被编造。

**每次保存只记一条纠正而不是每字段一条。** 用一条记录携带字段列表会更小。它落选是因为登记表的编辑载荷只指名一个字段及其前值与后值，而成熟度报告正是从这些记录里统计被编辑的字段。

## 后果

- `FaberLoomBoardIteration` 携带 `lockBy`；面板把它与开启尝试时使用的会话比较，而不指名任何会话的尝试读作本标签页自己的。
- 每个受锁约束的迭代 Remote 都要求 `actorSession`，`boardIterationResume` 不再接受不带会话的尝试：重开的尝试属于重开它的标签页。
- `boardIterationApply` 回答 `FaberLoomBoardIterationApplyResult`，`boardSaveEdits` 回答 `FaberLoomBoardEditResult`，两者都在已提交的值旁携带 `correctionError`，因此失败的纠正绝不会与失败的命令混淆。
- 十个本地化键承载另一个标签页的提示及其说明、丢失锁之后的暂停、文本已保留那一行、转移工作的提示及其比较与恢复操作、以及纠正那一行，面板没有任何硬编码字符串。
- `FaberLoomBoardDetail` 携带 `transferredDrafts`，视图在每次读取详情时都读取该列表；那里失败的板读取会让详情失败，而不是隐藏读者可能需要的草稿。
- `FaberLoomBoardIterationContext.summary` 与 `draftSummary` 可为 null，任务对话会指明缺失而不是从空摘要开始；未声明 `providerDataClassCeilings` 时，每个上下文都只有元数据。
- 已应用迭代的纠正以草稿的摘要作为指令；既没有存储摘要也没有应用摘要的尝试无法描述自己，登记表会拒绝该纠正，面板将之上报。
- 视图在每次应用前读取条目与保留的草稿、在每次编辑前读取条目以做差异；失败的读取只损失纠正的细节，绝不损失命令。
- 续期间隔来自 `iterationStatus().renewalSeconds`，因此面板不保留 D-09 数值的副本。
- 第二个标签页无法接管尝试：它一直阅读，直到第一个标签页退出或锁过期，而板把后者当作“保存并退出”（W-44）。
- 标签页会话存放在 `sessionStorage` 中，因此从迭代对话回到 Mesa 时，本标签页开启的尝试仍然属于自己，而不会被读作另一个标签页的；重开草稿也会指定该会话，因此重开的尝试从不是匿名的。
- 面板在尝试已死之后写入的文本仍然可达：板提供条目最新的保留草稿，无论条目是否链接它，因此后到的行由 `resumeIteration` 重开，而不是留下没有任何命令能到达的工作；被新尝试替换的草稿不会被提供。

## 验证

`packages/faberloom/view/tests/board-iteration.spec.ts` 证明视图一半：投影携带 `lockBy`，续期转发尝试 id、代次与会话并回答尝试，每个受锁约束的写入都转发会话，应用记录一条带范围、指令、差异、轮数、血统、数据分级与所用字段的 `iterate` 纠正，暂定分级随之传递，保存为每个变更字段记录一条带前值与后值的 `edit` 纠正，用条目已有值写入的字段不记录任何纠正，被拒绝的纠正仍然回答已提交的尝试与已提交的详情并带上消息，只读身份被拒绝每一次迭代写入。上下文套件证明 W-48：已声明的提供者收到摘要与工作草稿，未声明的提供者只收到元数据，较低的上限丢弃较高上限允许的内容，暂定分级即使在上限最高时也不发送任何内容，空策略失败即拒绝，会话未指名提供者时采用配置的默认提供者。详情套件证明 W-98：条目列出冲突移交给它的草稿及其键、基础版本与来源，而一次分配读取板回答的那个有效条目，而不是视图原来持有的 id，恢复会转发键与会话并映射两种回答且不应用任何东西。尝试套件还证明提供的草稿保留其尝试 id 与 `archived`、`superseded`、`retained` 标记，并由 `draftLinked` 说明条目是否链接它。

`packages/client/ui-faberloom/tests/registration.client.spec.tsx` 证明面板一半：计时器按投影的节奏以尝试 id、代次与会话续期；`LOCK_LOST` 续期先以已死尝试的草稿形式发送最后的文本，再回到带草稿的暂停状态，且从不保存条目；`LOCK_HELD` 续期把文本留在面板中并显示“文本已保留”那一行，同时把条目读作另一个标签页的，只读、一条提示、零出口；另一个标签页的锁以一条提示与零出口把条目渲染为只读，同时不尝试任何续期或写入；冲突转移的工作以一条提示出现，其比较操作读取草稿的差异，其恢复操作发送键与会话且从不应用，而过期的回答会渲染差异；条目从未链接的失效尝试草稿以未完成工作出现，并以尝试的基础版本重开；分配空间后会选中板回答的有效条目；失败的纠正在应用与保存之后都落在单行消息上。`packages/client/ui-faberloom/tests/task-chat.client.spec.ts` 证明提示词在被允许随行时携带钉住的摘要与未完成工作，并在提供者上限扣留它们时指明其缺失。

`apps/web/tests/mesa-panel.e2e.ts` 在组装后的产品上证明两者：保存草稿记录以条目摘要前值与后值为内容的 `edit` 纠正，以范围 `cuenta` 应用迭代记录带指令、差异、一轮，以及条目租户、空间、账户与数据分级的 `iterate` 纠正；在链接草稿之前就结束的尝试所留下的草稿被作为未完成工作提供，重开时不改变版本，并且只在应用尝试时才写入。`npx tsc -p tsconfig.host.json --noEmit`、`npx tsc -p tsconfig.client.json --noEmit`、`npx tsx scripts/verify-client-ui-i18n.ts`、`npx vitest run packages/client/ui-faberloom/tests packages/faberloom/view/tests` 与 `DSH_SNAPSHOT=replay npx vitest run --config vitest.web.config.ts apps/web/tests/mesa-panel.e2e.ts` 均为绿。
