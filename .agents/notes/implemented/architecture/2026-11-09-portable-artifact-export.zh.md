# Agent Note: A portable artifact is a versioned, signed inventory, not a file copy

Status: implemented

[English](2026-11-09-portable-artifact-export.md) | 中文

## Problem

一个空间的文档与 harness 记录分散在不同存储：文档正文在授权 Git 提交，agent 与 skill 在投影，继承在空间层级。把文件复制到一个文件夹既没有完整清单，也没有可复现摘要，更无法区分“被排除的贡献”和“从未存在的贡献”。用 regex 猜测引用要么漏掉依赖，要么把会话拉进来；直接写入输出目录则可能让无效产物替换有效产物。

## Decision

**规划器是纯函数；写入器拥有文件系统。** `planPortable` 合并空间自有贡献与父级允许继承的贡献，执行分类允许列表，解析显式依赖 id，分配产物路径，并返回文件、清单、摘要与逐文件拒绝。`stagePortable` 校验 staging 根，创建新的 `mkdtemp` 目录，写入每个文件，最后写 `manifest.json`，失败时只删除该目录。目录存在之前计划已经完整。

**格式、内容与软件有三个版本。** `formatVersion` 是布局，`contentVersion` 是规范清单的 `sha256:`，`softwareVersion` 是生产者版本。规范 JSON 对对象键排序并保留数组顺序。清单摘要排除 `digest` 与 `signature`，因此不会自签名；分离 Ed25519 签名覆盖包含摘要的规范清单。公钥是外部提供的信任锚，绝不存入产物。

**导出是允许列表加具名拒绝报告。** 只包含 `N0`、`N1` 与 `N2`。缺失、未知或矛盾分类在任何元数据拼写下都被拒绝；被排除贡献绝不进入清单、库存或标题，也不写脱敏标记。会话或转录按类型、已知存储路径（英文或西班牙文）、元数据或依赖被拒绝，即使属于同一空间。内容、元数据键与值、id、标题、路径与媒体类型扫描私钥和常见令牌形状；命中拒绝该贡献且机密不写入。报告为普通拒绝给出路径与原因，对分类、会话、机密或拒绝继承使用 `(restricted)`，避免报告本身泄露被排除标题。

**继承最小且固定一个父修订。** 父贡献只有在标记为可继承且按贡献授权时才被考虑。子级排除优先，同 id 的子级替换父级，两个子贡献不能复用 id，同一路径被两个不同 id 声明则拒绝而不是按读取顺序解决。父修订记录在清单中。

**依赖是 id，不是文本匹配。** 贡献用 `dependsOn` 命名 id。缺失、被拒、会话或循环依赖会拒绝依赖者；绝不静默截断。依赖闭包决定同一请求中还有哪些内容进入产物。

**路径在写入前校验，staging 是原子的。** traversal、绝对路径、盘符、反斜杠、Windows 设备名、保留 manifest 名、大小写别名、双向字符、非配对代理项以及把文件当目录都会被拒绝。缺失或符号链接的 staging 根在创建目录前被拒绝。写入后重新列出新目录：路径集合必须等于计划，每个文件必须是单一常规链接；否则删除目录。文档通过 `git cat-file blob` 与 `--no-replace-objects` 读取；修订必须是完整的 40 或 64 位十六进制提交 id 且解析回自身，因此 replace ref、短 id 和长得像哈希的分支名不能替换内容。投影适配器映射 agent、skill、workflow、routine 与 memory，但不赋予投影原子性。

## Alternatives considered

**把签名放进 manifest。** 签名要么覆盖自身，要么摘要必须排除被签对象内部的字段。分离签名让两件事分开，并允许调用方独立保存信任锚。

**把公钥嵌入产物。** 这等于用产物自带的密钥认证产物，能替换产物的人也能替换密钥。公钥属于消费者的信任库。

**用 regex 过滤正文引用。** regex 分不清依赖和示例，漏掉间接依赖，还可能把会话路径拉进来。显式 id 让闭包可判定、可测试。

**直接写入请求的输出目录。** 无效计划或写入失败会让先前有效产物被部分替换。每次运行新目录使“无效 staging 不替换有效输出”成为结构保证。

**默认继承所有祖先。** D05 要求按贡献继承且显式排除优先。最小父级与授权模型实现该规则，但不声称属于 3B.1 的完整多级层级。

**现在就压缩产物。** tar 或 zip 会隐藏清单，并增加摘要必须计入的新格式。目录可检查、可复现，且已是后续打包/传输切片的稳定输入。

## Consequences

调用方得到一个带完整清单、可复现清单摘要、分离签名与拒绝报告的目录。两个相同请求在不同 staging 目录产生相同清单与摘要；内容、元数据、身份、分类或软件变化会推动各自拥有的版本。被拒贡献只影响其依赖者，不影响整个产物。代价是一个固定父修订而非完整层级、目录而非压缩包、Windows 安全路径限制，以及本包之外的签名密钥管理。分类仍来自调用方的服务端策略：规划器执行允许列表，但不会发现调用方从未提供的类别。会话规则基于信号：如果记录的种类、已知存储路径或元数据没有把它标识为会话，它就可能看起来像文档，因为导出器不读取会话存储。
