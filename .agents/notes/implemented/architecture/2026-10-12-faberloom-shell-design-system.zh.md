# Agent Note: 采用 FaberLoom 外壳——五套调色板、分组导航、顶栏与自适应侧栏

Status: implemented

[English](2026-10-12-faberloom-shell-design-system.md) | 中文

## Problem

已登录客户端当时只有一套浅色、一套深色主题和一个开关、一层扁平的侧栏行，以及没有顶栏、也不处理窄于桌面布局的窗口的三列框架。`Diseño entrelazado 3x3 Faber-Loom` 中的品牌系统定义了五套完整调色板，把导航归入带计数的模式与手风琴分组，并要求顶栏带有搜索座位与侧栏控件，且侧栏在窗口变窄时退出文档流。在缩放、浮动或分屏的桌面窗口上——桌面应用的常见情形——侧栏仍要求占用轨道，导航随之不可用，而产品为自己选择的调色板根本无从选择。

## Decision

**调色板即已注册主题。** `packages/client/ui-theme/src/theme-palettes.ts` 是这一目录：从品牌书逐字誊写的五套调色板——`dark`（Faber Warm，默认）、`slate`、`mono`、`light`（Paper，默认）、`cloud`——每套按角色映射到共享的 `--dsw-alias-*` token（表面、墨色、细线、强调色与四种功能状态），并各自带有 `colorScheme`、底色与品牌名。浏览器侧在构造时用该目录填充 `BUILTIN_THEMES`，因此指名任一调色板的持久偏好能在首次采纳时就解析成功，而不会退回默认；`light` 与 `dark` 仍是 `system` 偏好取舍的那一对。调色板名是专有名词，在所有语言中保持原样；只有深色/浅色分组标题随词典翻译。

**持久偏好覆盖整个目录。** `THEME_PREFERENCES` 由该目录的 id 加 `system` 派生（`[...THEME_PALETTE_IDS, 'system']`），因此 settings schema 接受所有内置调色板，既有的写回守卫也无需改动即可工作。插件在运行时注册的主题仍可选择、也照常参与合成，但没有持久值。

**两个面读取同一目录。** 宿主侧此前只认识浅色与深色：`boot-theme.ts` 固定绘制 `#fff` 或 `#151517`，并从三值联合派生 `body[data-ds-dark-theme]`。现在它通过同一目录解析偏好——调色板 id 会在首帧绘制前用该调色板自身的底色与其配色方案绘制，而 `system` 与本构建不认识的 id 退回中性配对并使用 `prefers-color-scheme` 查询。

**侧栏脚部承载两个菜单。** 单个主题开关变为调色板菜单：按配色方案分组列出所有已注册主题，每行带取自该主题自身定义的色样，其上是跟随系统；旁边是列出已注册语言的界面语言菜单。两者都放在 `packages/client/ui-faberloom`，因为 `sidebar.footer.action` 座位位于 `ui-theme` 的引用闭包之外，且各自通过自己的服务（`theme`、`locale`）写入。

**导航归入模式与手风琴。** `sidebar.panellist` 新增三个可选列表选项——`mode`、`group`、`badge`——像 `label` 一样按投影解析。`packages/client/ui-slots` 把它们原样带在已存储条目上，`packages/client/ui-sidebar` 把它们投影进面板元数据，`packages/client/ui-faberloom` 为自己的分区声明它们（Operar / Aprender / Admin，每块领域一个主题分组，且只在实时概览确有数字处显示徽标）。侧栏在存在多个模式时渲染模式栏、每个分组渲染带行数的手风琴；当没有行声明模式或分组时，扁平列表保持原样。

**框架拥有顶栏与自适应区制。** `packages/client/ui-layout` 在列之上渲染 54px 顶栏，带品牌座位、中部座位与动作座位（三者都在此声明，且都无回退），以及侧栏开关。低于 1024px 时左列作为抽屉退出文档流，带遮罩、Escape 关闭与焦点归还，右栏悬于画布之上而不再占用轨道；低于 768px 时画布即页面。区制取自框架实测宽度，因此浮动或分屏窗口无需设备信号即可落入其中。

## Alternatives considered

**让 `ThemePreference` 保持封闭联合并手工加入三个新调色板 id。** 这会在第二个模块里重复调色板 id，并在新增调色板时漂移。从目录派生元组保持单一列表：id 只在两个面都已读取的模块里声明一次。

**让第三方主题 id 也能持久化。** 该持久字段跨越的宿主 schema 无法枚举运行时装配的注册表，而引导样式对未知 id 没有底色可绘制。内置目录就是可持久化的集合；插件主题在会话内合成，其 id 不写入。

**在插槽注册表上用通用的 `meta` 包，而不是三个具名列表选项。** 注册表的列表类型本就携带行展示字段（`label`、`order`），而无类型的包会让拼错的键静默消失。三个具名可选 thunk 让类型系统对所有者可读的内容保持诚实。

**在运行时构建之后从 `apply` 注册额外调色板。** 运行时在构造函数中采纳持久偏好；之后再注册意味着读取某个持久调色板 id 时它仍未知，会静默重置为默认。在构造时播种内置集合消除了这一顺序隐患。

**无论调色板如何，引导只绘制中性配对。** 深色调色板会在外壳挂载前闪出中性冷调底色——每次加载都可见。读取目录底色只多一次查找，却消除了闪烁。

**由 `ui-sidebar` 自己拥有的每侧栏抽屉。** 侧栏宽度、缩放手柄与跨越状态都在布局 store 中；侧栏里的抽屉需要知道框架宽度，并会在同一区制下让右栏得不到预留。框架里单一实测区制让两侧栏保持一致。

**跟随选中行模式的模式栏。** 背景选中变化时切换导航会把用户脚下的地移动；模式栏保持用户的选择，而自动展开的是选中行所属的分组。

## Consequences

导航现在可伸缩：行的归属由声明者决定，分组无需侧栏知道「分组」的含义，而没有分组元数据的分区渲染与此前完全一致——三个选项都是可选的，扁平列表保留自己的快照。顶栏的三个座位在被注册前都是空的，这是有意的：框架不附带无用的搜索框。调色板菜单列出注册表实际持有的内容，因此之后加入的主题包无需改动菜单即可出现，且其色样来自该主题自身的 token。引导样式现在绘制调色板底色，这会改变注入的 index 字节：Linux 下 web 快照通道记录的期望值需要这次有意刷新。

接受两点限制。设置中的「外观」行仍只提供默认配对加 `system`——五套调色板可从脚部菜单到达，把该行并入调色板列表是另一项改动。插槽目录的列表选项是策展文本，因此向 `ctx.slots.register` 添加这三个成员时，也在同一改动中更新了 `scripts/gen-client-catalog.ts` 及其 spec；未来的列表选项必须照做。
