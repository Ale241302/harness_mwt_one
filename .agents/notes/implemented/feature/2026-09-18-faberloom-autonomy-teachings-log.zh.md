# Agent Note: 选择性自主权、版本化教学与案件日志到达产品

Status: implemented

[English](2026-09-18-faberloom-autonomy-teachings-log.md) | 中文

## 问题

计划视为核心的三项能力已经实现并有覆盖，但在产品中无法触达：

- **自主权**（§10，E7）：`ctx.faberloomAccess` 持有选择性的、按动作授予的授权与一个 `check`，而没有任何东西咨询它。带效果步骤的例程无论 owner 是否曾授权该动作都会执行该效果，撤销授权也改变不了任何事。
- **教学**（§9.1，E7）：`ctx.faberloomMemory` 持有一切：带范围、来源、作者、替代、使用次数、情境绩效、迟到错误与可移植快照的版本化教学。Memoria 面板读写的是 TencentDB 代理记忆，因此一次纠正无处安放，无法复核、版本化或撤销。
- **案件日志**（§9，E6，界面 3 与 9）：执行只存在于 Rutinas 面板中，一次一个例程，没有界面展示案件收到什么、做了什么、花了多少，也没有事后纠正结果的地方。

## 决定

**自主权由引擎强制，由面板授予。** 在定义中记录了效果的步骤之前，例程引擎询问 access 服务：owner 是否已授予该例程声明的动作 —— 取它的第一个权限项，缺失时退回 `faberloom.effect.<stepId>` —— 并以该例程作为授权的上下文。拒绝即失败：该步骤被标记为 `NOT_AUTHORIZED:<reason>` 失败，执行进入 `needs_review`，因此案件落到 Mesa 而不是直接执行。检查在每次效果之前运行，因此 `REVOKED` 与 `EXPIRED` 会阻止下一次。引擎把 access 服务声明为注入，因此在没有授权的组合里效果根本无法运行。授权只能从 Conexiones 面板创建与撤销：能给自己授权的模型会推翻「学习永不扩大权限」这条规则。

**教学与记忆服务器共存。** 模型的活跃记忆仍是 TencentDB，由代理注入；原生教学注册表是产品自己的纠正记录，Memoria 面板现在同时显示两者。教学可以手工记录，也可以从案件应用；可以编辑（产生新版本并保留旧版本）、撤销，并连同其来源、范围、使用次数与背后的情境绩效证据一起阅读。任何一方都不会把另一方的行复制过去。

**案件日志自成一屏。** Ejecución 列出每一次执行及其所属例程、状态、等待或原因与截止期限；检查器渲染计划中的日志字段 —— 输入、上下文、决定、执行（每一步的状态、原因、记录文本以及是否记录效果）、成本、复核、效果 —— 以及一张纠正表单，其处理方式与教学文本会创建闭合回路的教学。行携带例程名、启动案件的事件、每一步的原因与效果标记、以及创建时刻，全部在调用时投影。

## 考虑过的替代方案

- **只在工具里强制自主权。** 否决：例程步骤经由引擎运行，而不是经由模型工具，因此工具侧的守卫会让计划自己的例子失去保护。
- **让模型授予授权。** 否决：它颠倒了 §10。查询与撤销可读；授予是人的行为。
- **用原生教学取代记忆服务器。** 目前否决：服务器会向每次模型调用注入上下文，而注册表不会；注册表回答的是「我们纠正过什么，它是否仍然有效」。
- **把案件日志放进 Rutinas 面板。** 否决：计划把「Rutinas」（定义）与「Ejecución」（发生了什么）分开，案件必须在不了解其例程的情况下可读。

## 后果

- 带效果的例程会停在 `NOT_AUTHORIZED`，直到 owner 授予其动作；撤销会阻止下一次效果 —— F16 与 F17 成为可执行的产品行为，而不只是引擎测试。
- 从案件应用的纠正会成为以该案件为来源的教学，之后可以编辑或撤销而不丢失其历史。
- 日志让人在判断结果的地方看到等待的截止期限与效果标记。
- 尚未按案件记录成本，因此日志会如实说明，而不是显示一个没人测量过的数字。
