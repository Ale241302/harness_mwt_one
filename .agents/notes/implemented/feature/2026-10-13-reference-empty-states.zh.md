# Agent Note: 显示 `@` 文件区块的空状态

Status: implemented

[English](2026-10-13-reference-empty-states.md) | 中文

## Problem

`@` 菜单的文件部分每次查询只列出工作区中的一个目录，并且仅渲染它找到的行。没有子条目的目录，以及子条目被键入过滤条件排除的列表，都不产生任何行，于是用户键入 `@`，读到的菜单对自己正在浏览的文件夹一言不发；若同时也没有匹配的会话行，菜单会直接关闭。渲染层让情况更糟：就绪但零条目的分组渲染为 null，而 source 发布的每一行都是键盘高亮与指针按压能够触及的选项——于是「一行说明」唯一可用的形态，是一个选中后什么也不插入的选项。

## Decision

**空结果是一行，而不是静默。** `packages/client/ui-reference` 在自己的字典命名空间下新增两个键——`Empty folder`／空文件夹／«Carpeta vacía» 与 `No results`／没有结果／«Sin resultados»——当 `browseCandidates` 没有产出任何条目行时发布其中之一：子条目无法被菜单提及的列表读作空文件夹，而子条目被过滤条件排除的列表读作没有结果。模糊名称搜索在索引无结果时也加入同一行「没有结果」；被截断的列表与列出失败的列表保留原有的提示位置。**发现**失败仍然不产生行：出错的查找不是空结果，也没有属于自己的诚实文案。

**信息行不是可选项。** 候选项类型新增 `note?: boolean`，文件区块的每一条信息行都带上它。reducer 在挑选首个高亮、在 `move` 与 `hover` 轮转高亮、在校验已停放的高亮时都会跳过提示行，因此提示行让其分组保持非空——菜单不关闭、文字可读——却从不声称自己是一个选择。`MenuView` 把它渲染为占一行位置的纯文本：没有 option id、没有 `aria-selected`、没有 pick 处理函数、没有下钻 chevron。于是只含一条提示的分组会把键盘让给其下的会话行，而不是把高亮停在一行无法行动的文字上。

## Alternatives considered

**仅在整个菜单本会为空时才渲染提示。** 拒绝：文件部分正是用户正在浏览的小节，而一个同时列出会话行的菜单仍然必须说明这个文件夹、或这个过滤条件，确实一无所获。

**把 `note` 字段放在就绪分组上而不是行上。** 拒绝：空是 source 的事实，不是渲染层的事实。无话可说的 source 不需要行，而 source 发布的每一行保持同一种形态。

**让提示行保持为没有 pick 值的普通行。** 列出失败的那一行此前正是如此。拒绝：一个什么也不插入的选项会误导键盘用户，高亮也会移到它上面；用标记把事实说出来更好。

## Consequences

`@` 文件区块不再静默：空文件夹、没有匹配的过滤条件、被截断的列表、列出失败的列表，各自用当前语言说明发生了什么。首个高亮永远是真实候选项；在只含提示行的菜单上按回车，与没有菜单时表现一致。提示行与会话行同属一个分组，因此一次名称搜索若没有匹配任何文件、却匹配了会话，现在会同时显示两者。该标记与渲染归 `packages/client/ui-input-trigger` 所有，任何 source 都能以同样条件发布信息行。各包 README 已说明被取代的决定：静默的空结果不再是刻意为之。

## Testing

`packages/client/ui-reference/tests/browser-plugin.client.spec.ts` 覆盖空文件夹中的裸 `@`、空的已下钻层级、排除所有子条目的过滤条件、无匹配的名称搜索，以及三种已注册语言下的两种状态；它还断言被截断与被拒绝的列表行带有该标记。`packages/client/ui-input-trigger/tests/core-menu.client.spec.ts` 覆盖 reducer 的跳过规则与只含一条提示的分组，`menu-view.client.spec.tsx` 覆盖渲染出的提示行及其缺失的 option id。
