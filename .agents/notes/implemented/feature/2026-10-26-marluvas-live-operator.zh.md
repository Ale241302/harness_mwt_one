# Agent Note: A Marluvas operator runs the mailbox end to end

Status: implemented

[English](2026-10-26-marluvas-live-operator.md) | 中文

## Problem

实时邮件例程会分类来信、留下回复草稿，并在邮件带有 OC、PO 或 SAP 时附加文档。这足够应付通用收件箱，但不足以支撑 Marluvas 业务：一个邮件线程可能同时带有形式发票、OC、SAP、装箱单、商业发票、DUA、BL/AWB 以及状态变更。操作员必须解析客户、运营主体、产品、尺码、两个价格、付款条件、佣金、日期、制品、收货、调拨和财务记录。通用分诊提示词会让模型自行即兴编排这一顺序，而且它无法加载该顺序所需的十个操作技能。

## Decision

**专用目录代理承担该操作。** `Operador Marluvas` 是一个按角色投放的种子代理（`admin`、`superadmin`、`ceo`），带有十个 `marluvas-*` 技能：主操作、邮件读取、业务档案、形式发票、SAP、状态、制品、海关、物流，以及质量/财务/结案。技能写明了 MCP 工具名、防护规则和工作顺序；代理提供人设、模型和技能清单。

**实时邮件例程在原位收敛，适用于运营邮箱。** 当所有者保存的 IMAP 用户名为 `alvaro@muitowork.com` 或 `506@muitowork.com`、角色为特权角色且代理存在时，内置的 `Vigía de correo` 定义会更新为 Marluvas 三步流程，并通过 `config.agentName` 把每个代理步骤指向该目录代理。例程保留原名，因此所有者不会在同一邮箱上得到第二个触发器。非特权角色、其他邮箱或代理缺失时，保留通用定义。

**绑定的是代理名称，而不是它的 id。** 代理 id 是本机局部的，镜像会在多台 home 之间同步例程，因此存储 id 会在每次同步时翻转，并在每次轮询时创建一个新的例程版本。步骤携带稳定的目录名称，`agentRuntimeFor` 在执行时解析它，因此每个 home 上的定义都相同。

**收敛比较的是归属字段，而不是存储形状。** 存储层会为每个可选步骤字段填入值（`config: {}`、`waitFor: null`、`maxAttempts: 1`），而作者输入会省略它们，因此原始 JSON 比较永远不相等，会把每次轮询变成一个新的例程版本。共享的 `routineDefinitionsMatch` 在比较前投影作者定义与存储定义。

**种子器只增加一项能力：目录升级。** 标记文件仍然记录每个已投放名称，因此已删除的代理不会被复活。早于新目录条目的标记文件现在只创建它尚未记录的名称；用户手工创建的同名代理保持不变并被记录。这样已有安装无需全新 home 就能获得 `Operador Marluvas`。

**模型不得凭空编造业务事实。** 技能要求身份校验、完整线程读取、附件和链接下载、来源引用，以及证据不完整时创建看板任务。技能还写明 MWT 运营与直采订单的定价规则，以及确切的形式发票行为：对 MWT 运营的业务档案，一次 `proforma_generar` 调用会生成三份 HTML 文档（客户、MWT、工厂）。

**邮箱是部署选择，不是硬编码凭据。** 代理使用已挂载的 `mwt` MCP；Web 网关按用户挂载，桌面端在登录时自助获取设备令牌。技能中不包含令牌、密码或 OAuth 密钥。

## Alternatives considered

**另建一个名为 `Operación Marluvas` 的例程。** 它会与 `Vigía de correo` 在同一条来信上触发，导致每封邮件运行两个代理，所有者还得记住哪个代理拥有该邮箱。收敛现有内置例程可以保持一个触发器和一个可见例程。

**在例程中写一个超长提示词。** 它会把十个技能复制到面板不可编辑的位置，无法按条件加载，而且会增长到难以阅读。技能包让每条规则紧邻它所约束的工具。

**为所有角色投放该代理。** 非特权角色无法调用操作所需的创建/更新工具，代理会出现在它无法行动的目录中。角色门控让目录保持诚实。

**硬编码 MWT.ONE OAuth 客户端或邮箱密码。** 桌面端已经从控制台获取设备令牌，Web 网关已经用登录身份挂载 MCP。签入凭据会泄漏，并把每个安装绑定到一个用户。

## Consequences

任一运营邮箱的特权所有者在下一次启动后会得到一个可工作、自主运行的 Marluvas 操作员：代理出现在目录中，实时例程处于活动状态，三步流程会读取线程、操作业务档案并验证结果。非特权所有者保留通用实时邮件例程。

本次变更给每个特权角色增加十个技能目录（内容相同，目录是角色目录的挂载方式）、一个目录条目，以及种子器中的一条升级路径。实时例程的名称仍为 `Vigía de correo`；对符合条件的所有者，其意图和步骤会改变，这正是内置契约已经允许的部署级收敛。

种子器的标记升级刻意保持狭窄：只增加名称，从不删除，也从不触碰手工创建的代理。未来某个目录条目若不应到达已有所有者，需要自己的门控，而不是空标记文件。

## Testing

`packages/faberloom/defaults/tests/defaults.spec.ts` 覆盖角色门控、十个技能、标记升级以及删除后不复活。`packages/faberloom/view/tests/email-actions.spec.ts` 覆盖白名单邮箱、非白名单邮箱和非特权角色。`packages/faberloom/inbound/tests/inbound.spec.ts` 覆盖轮询器在操作员代理存在时的投放。`packages/faberloom/routines/tests/equality.spec.ts` 固定作者/存储比较以及代理绑定变化。`scripts/verify-skills-catalog.ts` 检查每个技能目录的 frontmatter 和路由触发语。
