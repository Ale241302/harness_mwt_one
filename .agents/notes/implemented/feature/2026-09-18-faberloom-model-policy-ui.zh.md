# Agent Note: 代理的模型策略与看板的重新开启到达面板

Status: implemented

[English](2026-09-18-faberloom-model-policy-ui.md) | 中文

## 问题

计划所述的模型策略 —— 主模型、独占性、有序备选、授权升级、共享预算，以及用于填充它的推荐 —— 已经实现并有覆盖（F24–F31），但不可见。`ctx.faberloomAgents` 拥有池、解析器与推荐器；Agentes 面板只显示一行只读的主模型和一只开关，因此 owner 既看不到池，也无法修改引擎所解析的任何策略。同一处缺口也让 Mesa 无法重新开启案件：`board.reopen` 存在，却无从触达。

## 决定

视图暴露引擎已经拥有的东西，面板负责编辑它。

`ctx.faberloomView` 增加两个读取与两个写入：

- `models()` —— 池以普通行呈现（provider、model、能力、上限、费率、可用性）；
- `recommendModel(agentId)` —— 推荐器对某个代理的答复：推荐模型、带每个有用结果成本的有序备选、证据使用次数、临时标记与理由，以及不确定性的陈述；
- `saveAgent` 的策略补丁扩展为 `fallbacks`、`escalation`（授权模型、条件、`auto`/`manual`）与 `budget`（每次执行金额、货币、尝试与升级上限）；
- `reopenBoardItem(id)` —— 看板既有的 `reopen`，并带上其他写入同款的只读身份守卫。

Agentes 检查器新增 **Modelo IA** 区块：从池中取的主模型选择器、既有的独占开关、同一池上的备选与升级复选框、升级模式与条件、预算字段，以及一行推荐 —— 建议的模型与 *Aplicar* 按钮、带成本与证据的备选，以及推荐器报告的任何不确定性。Mesa 在批准与拒绝旁新增 *Reabrir* 按钮。

每个字段在 Remote 边界上都是普通 JSON 值，每次读取都在调用时从服务推导，因此面板中不镜像任何状态。

## 考虑过的替代方案

- **单独的模型池界面。** 否决：池的存在是为了被分配给代理，拆分会让分配变成跨两个界面的往返。
- **以 JSON 编辑策略。** 否决：计划的界面描述的是控件，而文本块会把校验推给 owner。
- **自动应用推荐。** 否决：计划说推荐本身不改变任何东西。按钮是显式的，而主模型选择器仍是该值唯一改变的地方。
- **在重新开启时提供纠正流程。** 与教学面一并推迟：今天重新开启只是让案件回到复核，把纠正与教学关联起来需要仍然休眠的记忆面板。

## 后果

- owner 能看到例程将要使用的整套策略并加以修改；解析器仍在执行时决定。
- 推荐器的不确定性在选择发生的地方可见，因此没有费率或证据的池会如实说明，而不是暗示存在最便宜的模型。
- 重新开启会让已复核的案件回到看板；不会自动重跑，之前复核的历史保留。
- 每次执行的隐藏会话仍使用部署的默认模型：把策略应用到代理运行路径是另一项工作。
