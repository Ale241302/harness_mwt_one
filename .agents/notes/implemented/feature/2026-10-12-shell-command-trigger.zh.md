# Agent Note: 在输入框中键入 `!` 请求模型运行一条 shell 命令

Status: implemented

[English](2026-10-12-shell-command-trigger.md) | 中文

## Problem

输入框的触发字符是用于命令的 `/` 与用于文件、会话引用的 `@`，两者各自经由产品已经拥有的路径解析：命令通过客户端的命令服务运行，引用插入模型会读取的 token。想让模型运行一条 shell 命令的用户只能把它当作普通文字键入，并寄望模型把它读成一条命令；没有任何手势把一条命令命名为命令。

## Decision

**`!` 是 `/` 与 `@` 之外的第三个触发字符。** `packages/client/ui-input-trigger` 新增它，在光标下键入它会通过 `src/core/shell-command.ts` 中的纯语法（`activeShellToken`）把该行剩余部分侦测为命令 —— 含空格，因为 shell 命令不是一个单词。`src/client/shell-source.ts` 里的内置来源在 Shell 标题（即该来源名自身的 `slash.menu` 键）下显示一行，以命令为标签、以本地化的「运行这条命令」提示为描述；选中它会把 `!` token 替换为模型读取的请求文本，提交时同一段文本作为用户消息发送。

**插入的文本是面向模型的协议形式。** `formatShellCommandMention` 产出一个字符串 `Run this shell command: <command>`，它既是用户在草稿中读到的文本，也是模型收到的提示文本；语法拒绝空命令与携带控制字符的命令。它刻意不做本地化，理由与 `@path` mention 不做本地化相同 —— 它是模型读取的协议，而不是产品显示 —— 而行自身的标签与提示仍通过 `slash.menu` 字典归本地化所有。

**浏览器不新增任何执行路径。** 插入的文本是用户的普通消息，因此模型用它自己的 shell 工具运行该命令，仍受已经约束该工具的沙箱与审批策略约束；浏览器里没有任何东西运行它，输入框也不知道模型是否照做。模型拒绝执行时，该请求就作为普通消息文本留在那里。

**加宽 `TriggerChar` 没有动已发布的 lexicon 域。** `TriggerChar` 变成 `'/' | '@' | '!'`，但输入框的装饰扫描只读 `/` 与 `@`，因此 lexicon 域保持 `'/' | '@'` —— 即触发包命名为 `ReferenceTriggerChar` 的那个联合 —— 而不是把 `TriggerChar` 向下转型。因此 `packages/client/ui-conversation/src/client/contract/input.ts` 中的会话契约保持其 `readonly trigger: '/' | '@'` 与 `ReadonlyMap<'/' | '@', readonly string[]>` lexicon 快照不变。

## Alternatives considered

**一个真正从输入框运行的手势。** 让输入框自己运行所键入的命令，需要一条已经受约束的、面向用户组合命令的路径，而这样的路径并不存在：唯一的 shell 执行是模型的工具，审批请求必须是回合内含的、并且指名一个工具，也没有任何 Remote 为某个会话运行一次性命令 —— 终端 Remote 在转录之外的一个侧边栏标签页里打开一个 PTY，那是一个 PTY，而不是受约束的一次性执行。因此一个真正的手势将意味着一个新的 Remote 加上一个会话事件加上审批接线，即工具之外的第二条执行路径，所以该手势改为请求模型。

## Consequences

用户得以把一条命令命名为命令：输入框显示一行 Shell，选中它就把键入的那一行变成模型读取并用自己 shell 工具运行的请求，因此约束该工具的沙箱与审批策略不变，浏览器仍然没有任何执行路径。插入的文本不做本地化，其协议引导语在草稿与提示里是同一个字符串。

这项选择带来两项限制。该手势是请求模型，因此模型拒绝执行时该请求作为普通消息文本留下，命令永不运行。并且已发布的 lexicon 域仍是 `/` 与 `@`：`!` token 不会被当作引用装饰，因为输入框的装饰扫描只读那两个引用触发字符。

验证：该包的客户端测试覆盖 `!` 语法（命令是该行剩余部分，另一个 token 内部的 `!` 以及 `!=`、`!==` 运算符都不是触发字符，语法拒绝空命令或携带控制字符的命令）、那一行 Shell 及其本地化文案、选中后插入的面向模型形式，以及让 shell 命令内部的 `@` 仍能抵达文件与会话引用的侦测顺序。
